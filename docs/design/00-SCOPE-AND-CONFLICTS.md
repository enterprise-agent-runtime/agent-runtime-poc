# 00 Scope summary and Conflicts

Design set for the Warden PoC. Inputs: WRD-00 to WRD-16 (v0.5 / WRD-16 v0.1, dated 25 to 26 September 2026) and the 26 diagrams in `img/`. Precedence applied: WRD-16 > companion document for the subsystem (WRD-02 to WRD-11) > WRD-00. Where WRD-16 is silent, the companion applies without being enlarged.

## 1. Scope summary (≤ 200 words)

The PoC proves the Warden thesis end to end on one macOS or Linux workstation. A Go daemon (`wardend`) exposes JSON-RPC 2.0 over an owner-only Unix socket with a token; the `warden` CLI (full parity) and a Tauri 2 + React desktop (seven screens, six states) are its only clients. One fixed workflow runs two declarative agents: `coder` (plan, implement, repair) and `verifier`: plan → G1 → implement → verify → repair (max 1) → G2 → deliver, sequential, one worktree per session. Every agent-requested process runs in a per-task L1 sandbox (Seatbelt or bubblewrap + seccomp; L2 Docker optional) through `warden-exec`, with no credentials and no network except a per-task deny-by-default egress proxy. A YAML + CEL policy engine (two layers, three effects, four approval scopes) authorizes every call. Models are reached host-side through `anthropic-messages` and `openai-compatible` (local T0, company-hosted T1, Azure tenant T2, vendor T3) and through the Copilot SDK harness (T4; Codex and Claude Code optional). A tier-aware router admits only T0 to T2 for `confidential` data. Everything is a hash-chained SQLite event; artifacts are content-addressed with provenance; `audit export` and `audit verify --strict` prove H2 and H5.
