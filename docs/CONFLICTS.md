# Conflicts

Every place where the design output (or a specification document) contradicts `CLAUDE.md`, WRD-16 or an invariant, with both references, the precedence rule applied (`CLAUDE.md` §2) and the resolution or "needs owner". Maintained by the implementer; WRD and design documents are never edited. The design set's own register (CF-01 to CF-44 in `design/00-SCOPE-AND-CONFLICTS.md`) covers conflicts *between source documents* and is applied as written unless a row below overrides it.


Sources compared: `CLAUDE.md` (the contract), `docs/WRD-16-PoC-Concept-and-Build-Plan.md` (scope), and the Claude Design output in `docs/design/` (`00-DESIGN-CORE`, `00-SCOPE-AND-CONFLICTS` (CF-xx), `OPEN-QUESTIONS` (OQ-xx), A01–A18, B01–B09). Line numbers (`l.`) refer to the files as delivered on 2026-09-26. Paths are relative to `docs/` unless stated; `design/` = `docs/design/`.

Precedence rules applied (CLAUDE.md §2):

- **R1**: scope and invariants. CLAUDE.md and WRD-16 win; no design document adds scope or weakens an invariant. Where CLAUDE.md and WRD-16 disagree with each other, CLAUDE.md §3–§5 ("fixed decisions, never reopen") and the build prompt are followed, and the WRD-16 text is flagged for the owner.
- **R2**: implementation detail. Design > companion WRD (WRD-02…WRD-11) > WRD-00, unless CLAUDE.md fixes the detail itself (CLAUDE.md l.3: "this file … win[s]").
- **R3**: a design document that contradicts an invariant or a fixed decision is a **defect**. It is recorded here and the invariant is implemented.

Status: **Resolved** = we implement the stated resolution now. **Needs owner** = an interim choice is stated and implemented, but the owner must confirm or overrule.
